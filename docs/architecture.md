# Finger Trader Python SDK V1 Architecture

## Scope

V1 is a small, local, dependency-free strategy authoring and bar-dispatch foundation. It defines stable value objects and lifecycle hooks that can later be generated by the Finger Trader Visual Strategy Builder.

V1 includes:

- OHLCV bars with symbol, timezone-aware timestamp, and timeframe.
- Strategy parameters and per-run context.
- Streaming and batch SMA, plus cross-above and cross-below predicates.
- Buy, sell, and close intent signals.
- A one-run chronological dispatcher that invokes strategy lifecycle hooks.

V1 does not include market-data fetching, a backtest engine, optimization, portfolio accounting, paper trading, order submission, or live execution. A returned signal is only strategy intent. The SDK does not claim an order was accepted or filled.

## Package boundaries

- market_data: immutable Bar and common timeframe labels.
- indicators: pure/local calculations with no dataframe dependency.
- strategy: parameter declarations, lifecycle hooks, and run context.
- signals: typed strategy intent objects.
- runtime: chronological bar delivery and signal collection. It does not simulate fills.

Orders, portfolio, and risk packages are intentionally not created until their contracts and local behavior are designed.

## Runtime flow

1. The caller creates an iterable of bars.
2. StrategyRunner calls on_start(context) once.
3. Bars are delivered in order; order is validated independently per symbol.
4. on_bar(bar) may return one signal, an iterable of signals, or None.
5. on_stop() runs after a successful start, including when bar processing fails.
6. Signals are returned to the caller; no network request or order side effect occurs.

Timestamps must be timezone-aware. UTC timestamps are recommended at system boundaries. Bar values are floats for V1 and should be converted explicitly at data ingestion when source APIs provide decimal strings.

## Finger Desk reference findings

The desktop UI is not an SDK dependency. Relevant existing boundaries found in finger_desk:

- The quant page is a Flutter workbench. Strategy names are persisted locally, but its market datasets and optimization values include demo data. Its _runJob path only waits briefly and shows a completion message; it does not execute historical backtests or parameter optimization. The code editor is a UI component and is not connected to a Python process runtime in this project.
- Historical candles are fetched by ApiProvider.marketGetKlineList from /app-api/v1/market/kline-list. The request currently contains market, ticker, interval, startTime, and limit; response candles carry OHLCV and time fields.
- Market updates are distributed through MarketSocketService, market subscription helpers, and app events such as KLineFrameEvent and MarketQuoteEvent.
- OMS flows use existing app services and typed API DTOs. For example, spot wallet information is obtained through fundGetSpotWallet; holdings/history use orderGetHoldingOrders and orderGetTradeHistory; order placement uses orderCreateOrder and CreateOrderDTOO.

The SDK deliberately does not copy Flutter DTOs into a network client or submit orders. A future adapter should map authorized service contracts into Bar and keep credentials, account permissions, risk checks, and execution authority on the service/OMS boundary.

## Visual Strategy Builder compatibility

Generated code should depend on the public exports in finger_trader, not private runtime modules. Parameter names and signal classes form the initial V1 generation surface. Future changes to these names should be versioned and covered by compatibility tests before the desktop generator targets them.
